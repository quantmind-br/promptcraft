# Test Design: Story 2.5 - Command Listing and Discovery

Date: 2025-01-02  
Designer: Quinn (Test Architect)

## Test Strategy Overview

- **Total test scenarios**: 18
- **Unit tests**: 10 (56%) 
- **Integration tests**: 6 (33%)
- **E2E tests**: 2 (11%)
- **Priority distribution**: P0: 8, P1: 6, P2: 4

## Test Scenarios by Acceptance Criteria

### AC1: `promptcraft --list` scans both project and global directories

#### Scenarios

| ID           | Level       | Priority | Test                              | Justification                    |
| ------------ | ----------- | -------- | --------------------------------- | -------------------------------- |
| 2.5-UNIT-001 | Unit        | P0       | Directory scanner logic           | Core file discovery algorithm    |
| 2.5-INT-001  | Integration | P0       | Scan both project and global paths| Multi-directory discovery flow   |
| 2.5-E2E-001  | E2E         | P1       | Full CLI command execution        | Critical user journey validation |

**Test Details:**

- **2.5-UNIT-001**: Test `scan_command_directories()` function with mocked filesystem
  - Input: project_path, global_path
  - Expected: Both paths scanned and results merged
  - Mock: pathlib.Path.glob(), Path.exists()

- **2.5-INT-001**: Test with actual test directories containing .md files
  - Setup: Create temp dirs with sample .md files in both locations
  - Execute: Call directory scanning with real paths
  - Verify: All files from both locations discovered

- **2.5-E2E-001**: Test complete CLI workflow
  - Execute: `promptcraft --list` in test environment
  - Verify: Command completes successfully and shows expected output

## Risk Coverage Mapping

### High-Risk Mitigations

- **PERF-001 (Score 6)**: Performance bottleneck
  - **Covered by**: 2.5-E2E-002 (load testing)
  - **Additional coverage**: Unit tests validate efficient algorithms

- **TECH-001 (Score 4)**: Cross-platform compatibility  
  - **Covered by**: 2.5-INT-001, 2.5-INT-002 (filesystem operations)
  - **Platform testing**: Required on Windows, macOS, Linux

### Medium-Risk Coverage

- **SEC-001 (Score 3)**: Path traversal prevention
  - **Covered by**: Path validation in unit tests
  - **Security focus**: Input sanitization testing

- **DATA-001, OPS-001**: File handling robustness
  - **Covered by**: 2.5-UNIT-007, 2.5-INT-005 (error scenarios)

## Test Environment Requirements

### Unit Test Environment
- **Framework**: pytest with unittest.mock
- **Mocks**: pathlib.Path operations, file system calls
- **Coverage**: Aim for >95% on core logic functions

### Integration Test Environment  
- **Setup**: Temporary test directories
- **Files**: Sample .md templates with various content
- **Cleanup**: Automated teardown of test artifacts

### E2E Test Environment
- **CLI**: Full promptcraft installation
- **Data**: Large set of template files (150+ for performance)
- **Platforms**: Windows, macOS, Linux (CI/CD)

## Success Criteria

### Functional Requirements
- [ ] All 18 test scenarios pass consistently
- [ ] Zero gaps in Acceptance Criteria coverage
- [ ] All error scenarios handled gracefully

### Non-Functional Requirements  
- [ ] Performance requirement <150ms validated
- [ ] Cross-platform compatibility verified
- [ ] No memory leaks with large file sets

### Quality Gates
- [ ] P0 tests: 100% pass rate required
- [ ] P1 tests: >95% pass rate required  
- [ ] P2 tests: >90% pass rate target

## Test Maintenance Strategy

### Ongoing Maintenance
- Update tests when CLI framework changes
- Add regression tests for any production issues
- Review test performance as file volumes grow

### Monitoring
- Track test execution time trends
- Monitor flaky test patterns
- Validate cross-platform consistency

This comprehensive test design ensures efficient coverage while maintaining focus on the highest-risk areas and most critical user functionality.
