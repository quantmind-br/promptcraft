# Story 2.3: Output Mode Selection with --stdout Flag

## Status
Done

## Story
**As a** user,
**I want** the option to output prompts to terminal instead of clipboard,
**so that** I can use the tool in different workflows and environments.

## Acceptance Criteria
1. `--stdout` flag option available for the main command
2. When `--stdout` used, prompt is printed to terminal instead of copied to clipboard
3. Success message changes to: "✅ Prompt for '/command-name' generated:"
4. Prompt content is displayed with proper formatting/indentation
5. No clipboard interaction occurs when `--stdout` flag is used
6. Flag is properly documented in help text
7. Flag works in combination with all other functionality

Based on Epic 2.3 requirements and CLI architecture:
- **Flag Implementation:** `--stdout` flag should be implemented as Click option parameter
- **Conditional Logic:** Success path should check flag presence to determine output method
- **Terminal Output:** When `--stdout` used, print prompt content directly to terminal with formatting
- **Message Changes:** Success message should change to indicate generation vs clipboard copy
- **No Clipboard:** Completely bypass pyperclip operations when `--stdout` flag is active
- **Documentation:** Help text must clearly explain the `--stdout` flag functionality
- **Compatibility:** Flag must work with all existing commands and error handling

### Click Framework Integration Specifications
For implementing the `--stdout` flag in the existing CLI:
1. **Flag Definition:** Add `@click.option('--stdout', is_flag=True, help='Output to terminal instead of clipboard')`
2. **Parameter Passing:** Update main command function signature to accept `stdout` parameter
3. **Conditional Logic:** Implement if-else logic to choose between clipboard and terminal output
4. **Success Messages:** Use different success messages based on output mode
5. **Help Integration:** Click automatically adds the flag to help text with provided help string
